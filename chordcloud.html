ChordCloud

Hybrid music recommendations with Spotify playlist creation.

RepositoryLive demoDemo pending

Why I built it

Spotify is my thing. I have a playlist for every possible mood, and sometimes multiple playlists for the exact same mood. But hey, we all get lazy sometimes. When I know the vibe I want and don’t feel like hunting for songs one by one, I just want something quick and easy. So I built ChordCloud to make the playlist for me :)

Architecture

  1. Natural-language prompt
  2. Search music documents
  3. Find matching Spotify tracks
  4. Spotify playlist

How I built it

Getting from a prompt to Spotify

I built the playlist app in Streamlit. A LlamaIndex agent uses local embeddings to search music documents for themes and a Groq-hosted model to interpret the request. The app uses Spotify search and the Spotify Web API to turn the result into a playlist.

Building a recommender I could test on its own

Separately, I built an engine with two sources of signal. The collaborative side uses cosine similarity between Last.fm listeners and gives more weight to similar listeners’ activity. The content side compares precomputed Spotify audio features. A hybrid ranker blends a track’s content score with a boost from the collaborative side.

Checking what the recommender recovers

For the offline collaborative-filtering evaluation, I hide one listened-to artist per sampled user and check whether the ranker brings that artist back in its top ten. I also added Pytest coverage for the collaborative, content-based, hybrid, and evaluation components.

Where it stands

The repo reports a 0.254 Hit Rate@10, 0.025 Precision@10, and 0.254 Recall@10 on a 300-user sample. Hit rate and recall match here because there is one held-out artist per user. These numbers describe the offline collaborative recommender. I’d use prompts from real listeners to evaluate the playlists produced by the separate Streamlit app.
