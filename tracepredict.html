TracePredict

Track incidents, group related alerts, and predict how serious they might be.

RepositoryLive demoDemo pending

Why I built it

This started as TraceVault, a Jira-style website for reporting incidents. Once I had somewhere to file a report and follow it through to resolution, I kept noticing places where I could do more. What if the same alert showed up twice? What would help someone figure out where to start? Those questions turned it into TracePredict.

How I built it

Giving alerts somewhere to land

I added signed webhook intake and a PostgreSQL queue, then moved case updates into a background worker. That split lets the app record an incoming delivery and process it separately. If processing fails, I can requeue the delivery without asking the sender to send it again.

Figuring out what counts as a duplicate

There are two things to decide here: whether this is another delivery of an alert I already saw, and whether a different alert belongs to a case that already exists. I kept those decisions separate so the case stays useful and the audit timeline can explain what happened.

Adding a prediction before the report is filed

I used the draft description, affected services, and history available at intake to estimate severity, likely cause, and time to resolution. I stored the model version and input snapshot with the preview so it can be compared with the outcome later. Report creation still works if the prediction is unavailable.

Checking the predictions in time order

I compared nearest-neighbor models with simple baselines. I split incidents into earlier development data, a later validation period, and a final test period. That makes it possible to ask whether the model helps on future incidents using information that was available when each report came in.

Where it stands

The app now connects reporting, investigation, and resolution, and the security queue can handle repeat deliveries. The bundled prediction demo uses 800 synthetic examples, so its results describe those generated incidents. For a historical model, the app can withhold a prediction when the test set has too little support or the model fails to beat the baseline.
