SpecMind

Self-hosted code intelligence with local retrieval and generation.

Why I built it

I’m a CS student, and if there’s one feeling I know well, it’s opening someone else’s project for the first time and wondering how they got from an idea to all of this. I want to know where things happen, but I definitely don’t have the patience to read allll the code just to find a starting point. So I built SpecMind to let me ask the question I actually have and jump to the bits of code that help answer it.

How I built it

Picking what goes into the index

I started with Python and used its AST to pull out functions, async functions, and classes. Each chunk has the symbol name, source, docstring, file path, and line range. I put that information in SQLite so it stays available after indexing.

Matching questions to code

I embed the name, docstring, and source together with all-MiniLM-L6-v2. When I ask a question, I embed it with the same model and use FAISS to find the nearest chunks by L2 distance. The returned positions map back to the original metadata.

Making answers easy to check

The FastAPI query route passes the retrieved context to a local Ollama model. I return the source references alongside the generated answer, so I can open the file and see what the model was working from. The CLI also gives me a way to work with the index without using a browser.

Where it stands

It can take a Python repository and return an answer with file and line references. The prompt currently includes only the first 300 characters of each chunk, so longer implementations can lose important context. I’d test questions that span multiple files and check the retrieved snippets separately from the generated answer.
